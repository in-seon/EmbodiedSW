# 팀 인터페이스 합의 필요 사항

CLAUDE.md 6장 기준, 목표 2(쓰러짐 감지) 팀원 및 하드웨어팀과 합의가 필요한 항목.
합의되는 대로 이 문서를 갱신하고 `config/config.py`의 해당 값을 채운다.

## 신호 연장 파라미터 (담당 파트)

- [x] **구역별 연장 시간 — `ZONE_EXTENSION_SEC` = {1:0, 2:3, 3:5, 4:3, 5:0}.**
      담당자 예시값이 아니라 국내 스마트횡단보도 운영 사례 기준. 3번 5초는 광주시("최대 5초")·
      음성군("5초 간격") 사례, 2·4번 3초는 서울시 "3~6초 연장"의 하한.
      → `docs/decisions.md` 2026-08-19 항목에 출처 링크. **팀 확인만 남음.**
- [x] **연장 누적 상한 — `MAX_TOTAL_EXTENSION_SEC = 10`.**
      강진군 자동연장 시스템의 "허용된 시간(5~10초) 범위" 상한. **팀 확인만 남음.**
- [ ] 연장 트리거 임계값 — `REMAINING_TIME_THRESHOLD_SEC = 5`.
      ⚠️ **이 값만 외부 근거가 아니라 설계 논리다**(1회 최대 연장량과 동일하게 설정).
      팀 논의로 확정할 것.
- [ ] **모형 스케일 검증** — 위 값들은 실제 도로 기준이다. 축소 모형에서 "5초 연장"이
      의미 있는 양인지 사람 모형을 실제로 움직여 확인하고, 과하면 비율(3 : 5 : 상한 10)을
      유지한 채 축소한다.
- [ ] 잔류 확정 프레임 수 — `ZONE_RESIDENCY_FRAMES` (실측 FPS 기반). **아직 `None`이라
      `--mode full`이 막혀 있다.** 값을 정하기 전까지는 `--confirm-frames 3` 처럼 주면 돈다.

## 캘리브레이션 / 속도 추정

- [ ] **횡단보도 모형 실측 치수** — `CROSSWALK_REAL_WIDTH_CM`, `CROSSWALK_REAL_LENGTH_CM`.
      **속도와 구역 분할 둘 다에 필요하다(우선순위 높음).**
      - 없으면 속도가 px/s로만 나오고 예상 통과 시간은 계산되지 않는다.
      - 없으면 구역도 화면 기준으로 나뉘어 **실제 거리로 균등하지 않다.** 사선 구도 예시에서
        1번 77cm / 5번 429cm로 5.6배 차이가 났고, 실제 한가운데가 3번이 아닌 4번 구역에 들어갔다.
        "정중앙이면 가장 길게 연장" 규칙이 엉뚱한 위치에 적용된다는 뜻이다.
      별도의 체스보드 캘리브레이션은 필요 없다 — `tools/zone_calibrator.py`에서 네 꼭짓점을
      찍을 때 `--width-cm` / `--length-cm` 만 같이 주면 된다.
- [ ] 카메라 최종 설치 위치 고정 후 캘리브레이션 수행 (카메라를 옮기면 zone 좌표·호모그래피 모두 무효).
- [ ] 캘리브레이션 해상도와 운영 해상도 일치 확인 (다르면 좌표가 통째로 어긋난다).
- [ ] 속도 윈도우 `SPEED_WINDOW_SEC` — 사람 모형을 일정 속도로 움직여 실측 오차 확인 후 조정.
- [x] **속도(ETA) 전송 — 구현 완료** (`USE_SPEED_FOR_EXTENSION`).
      **부족분 계산은 아두이노가 한다.** 파이는 잔여 시간을 모르므로
      `ETA x 1.25 - 잔여시간` 의 뺄셈을 할 수 없다. 두 숫자를 다 가진 쪽이 계산해야 한다.
      파이는 `EXTEND 5 7.2` 처럼 ETA를 실어 보내기만 하고, 플래그가 False면 `-`를 넣는다.
      → 아래 "아두이노 계약" 참고.
- [ ] **`USE_SPEED_FOR_EXTENSION`을 True로 켜기** — 기본값은 아직 `False`.
      켜기 전 순서: ① 캘리브레이션 + 실측 치수 입력 → ② `manual_camera_person_check.py`에서
      단위가 `cm/s`인지 확인 → ③ 사람 모형을 일정 속도로 움직여 속도·ETA 정확도 검증 → ④ 켜기.
      **실측 치수가 없으면 ETA가 `None`이라 켜도 `-`가 나간다(안전한 폴백).**

## 하드웨어 / 통신 — **아두이노 계약**

- [ ] **제어부/구동부 보드 구성 확정** — ESP32(제어부) + 아두이노 우노(구동부)는 **잠정안**.
      부저·신호등 LED·7세그먼트를 **한 보드**가 담당하기로 했고, 그래서 시리얼 채널도 하나다.

### 역할 분담 — 각자 자기만 아는 것을 판단한다

| | 아는 것 | 판단하는 것 |
|---|---|---|
| **라즈베리파이** | 영상, 사람 위치, 구역, 속도 | 잔류 확정, 쓰러짐 확정, **어느 구역이 점유됐나** |
| **아두이노** | 잔여 녹색 시간(7세그먼트) | **언제 연장할까**, 누적 상한, 사이클 리셋, 부저/LED |

"남은 시간이 5초 미만인가"는 카운트다운을 직접 세는 쪽만 답할 수 있고, "이 사람이 몇 번
구역에 있나"는 영상을 보는 쪽만 답할 수 있다. 이 분할 덕분에 파이 쪽 `signal_extend.py`가
200줄에서 130줄로 줄었고, "한 번 상한을 찍으면 영구 CAPPED" 같은 위험도 사라졌다.

### 프로토콜 (확정)

개행으로 끝나는 ASCII 한 줄. `SERIAL_BAUDRATE = 9600`(스케치의 `Serial.begin()`과 일치).

| 파이 → 아두이노 | 의미 |
|---|---|
| `NORMAL` | 연장 요구 없음 (아무도 없거나 양 끝 구역만) |
| `EXTEND <초>` | **앞으로 필요한 시간(초)**. 예: `EXTEND 7` — 연장할 초가 아니다 |
| `FALL` | 쓰러짐 확정 |
| `PING` | 연결 확인 |

| 아두이노 → 파이 | 의미 |
|---|---|
| `READY` | 부팅 완료 (파이가 이걸 기다린 뒤 전송을 시작한다) |
| `PONG` | `PING`에 대한 답 |
| `ERR <명령>` | 모르는 명령 |

**⚠️ 상태 메시지(`NORMAL`/`EXTEND`/`FALL`)에는 응답하지 말 것.** 13바이트를 9600bps로
내보내는 데 13.5ms가 걸린다. 초당 여러 번이면 그 송신 시간에 아두이노 루프가 묶이고,
TX 버퍼(64B)가 차면 `Serial.print`가 아예 블로킹된다. `PING`에만 `PONG`으로 답하면 된다.

### 전송 정책 — 파이 쪽 동작

- 상태가 바뀌면 **즉시** 보낸다.
- 바뀌지 않아도 **1초마다 같은 상태를 재전송**한다(`SERIAL_STATE_HEARTBEAT_SEC`).
  메시지가 유실돼도 1초 안에 복구되고, 아두이노는 이걸 워치독으로 쓸 수 있다.
- 값이 그대로면 하트비트 전까지 보내지 않는다. 사람이 2번→4번으로 옮겨가도 요구가
  같으면(둘 다 같은 값) 전송하지 않는다 — 아두이노 입장에서 같은 요구이기 때문이다.
- 종료 시 `NORMAL`을 보내고 닫는다(부저가 계속 울거나 연장이 남지 않도록).

### ⚠️ `EXTEND` 뒤의 숫자는 "연장할 초"가 아니다

**"이 보행자가 횡단을 마치는 데 앞으로 필요한 시간(초)"**이다. 아두이노가 빼야 한다:

```c
need = ceil(eta * ETA_SAFETY_MARGIN - greenRemaining);   // 부족분
if (need > MAX_SINGLE_EXTEND) need = MAX_SINGLE_EXTEND;  // 1회 상한 (아두이노 상수)
if (need <= 0) need = 0;                                  // 제시간에 건넌다 -> 연장 없음
```

파이는 잔여 시간을 모르므로 뺄셈을 할 수 없다. 뺄셈이 여기서 일어나려면 받는 값이
'연장량'이 아니라 '필요 시간'이어야 한다.

파이가 그 값을 정하는 방법(아두이노는 구분할 필요 없다):

| 파이 쪽 상황 | 보내는 값 |
|---|---|
| 속도가 잡히고 `USE_SPEED_FOR_EXTENSION=True` | 실측 ETA (예상 통과 시간) |
| 속도가 안 잡히거나 플래그가 False | 구역값 (거친 추정) |

**`MAX_SINGLE_EXTEND`를 꼭 두세요.** ETA가 이상하게 크게 나오면 한 번에 예산을 다 씁니다.
5초를 권합니다(구역 3번의 원래 값이자 광주시 사례값).

### 아두이노가 구현해야 할 것

- [ ] **`applied` 플래그와 재무장 — 이 둘을 같이 봐야 한다.**

      파이가 보내는 것은 "지금 3초 더해라"라는 **명령이 아니라** "이 횡단보도에 3초짜리
      요구가 있다"는 **현재 상태**다. 조건이 유지되는 동안 같은 줄이 계속 재전송된다
      (유실 복구용). 그래서 아두이노는 그것을 `pending` 변수에 담아 두고 **자기 조건이
      맞을 때** 적용해야 한다. 받을 때마다 더하면 녹색이 무한히 늘어난다.

      ```c
      // 수신부: 값을 저장만 한다 (여기서 적용하지 않는다)
      if (!strcmp(cmd, "EXTEND")) pending = neededSec;   // 저장만 — 여기서 적용하지 않는다
      else if (!strcmp(cmd, "NORMAL")) pending = 0;

      // 카운트다운 루프
      if (greenRemaining <= REMAIN_THRESHOLD && pending > 0 && !applied) {
          int need = pending;                       // ETA가 있으면 아래 항목대로 깎는다
          int room = MAX_TOTAL - totalExtended;     // 남은 예산
          if (need > room) need = room;             // 거부가 아니라 '남은 만큼'을 준다
          if (need > 0) {
              greenRemaining += need;
              totalExtended  += need;
              applied = true;
          }
      }
      if (greenRemaining > REMAIN_THRESHOLD) applied = false;   // ★ 재무장
      // 새 녹색 시작 시: totalExtended = 0; applied = false; pending = 0;
      ```

      **`pending`은 소비되는 이벤트가 아니라 유지되는 값이다.** 파이가 "지금 연장해!"라고
      타이밍을 맞춰 보내는 것이 아니라, "현재 이런 요구가 있다"를 계속 알려줄 뿐이다.
      그래서 잔여 12초일 때 받은 값이 잔여 5초가 됐을 때 그대로 쓰인다 — 파이가 그 순간에
      맞춰 다시 보낼 필요가 없다. (파이도 1초 하트비트로 계속 재전송하므로 이중으로 안전하다.)

      뒤집어 말하면 **낡은 값이 계속 남는다는 뜻이기도 하다.** 파이가 죽으면 아두이노는
      마지막 `EXTEND`를 영원히 들고 있게 되므로, 아래 무신호 워치독이 반드시 필요하다.

      **★ 재무장 줄이 핵심이다.** 이게 없으면 사이클당 한 번만 연장되고, 누적 상한 10초는
      영원히 도달할 수 없다(1회 최대가 5초이므로). 그러면 **느린 보행자를 한 번밖에 못
      도와준다.** 연장으로 잔여 시간이 임계값 위로 올라가면 무장이 되살아나고, 다시
      내려올 때 재평가한다. 무한 연장을 막는 것은 이 플래그가 아니라 **누적 상한**이다.

      타임라인 예 (녹색 15초, 임계 5초, 상한 10초, 사람이 계속 횡단보도 위):

      | t | 잔여 | 파이가 보낸 것 | 아두이노 | 누적 |
      |---|---|---|---|---|
      | 10 | 5 | `EXTEND 5` | +5 적용, 무장 소모 | 5 |
      | 11 | 9 | (재전송) | 잔여>임계 → **재무장** | 5 |
      | 12 | 8 | `EXTEND 3` (사람 이동) | `pending=3`, 아직 적용 안 함 | 5 |
      | 15 | 5 | (재전송) | +3 적용 | 8 |
      | 18 | 5 | (재전송) | 남은 예산 2 → **+2만** | 10 |
      | 21 | 5 | (재전송) | 예산 0 → 더 안 줌 | 10 |

      총 녹색 15 + 10 = 25초에서 멈춘다. **파이는 이 과정에 개입하지 않는다** —
      잔여 시간을 모르므로 개입할 수도 없다. 파이의 책임은 "요구가 있다/없다"를
      정확히 보고하는 것까지고, 총량 통제는 전적으로 상한이 한다.

- [ ] **⚠️ 서 있기만 하는 사람도 연장을 소진한다 — 알고 있어야 할 한계.**
      잔류 확정은 "횡단보도 안에 계속 보인다"까지만 보고 "건너는 중인가"는 구분하지 않는다.
      가운데서 멈춰 있는 사람이 있으면 상한 10초를 다 쓴다. 상한이 있어 위험하지는 않지만,
      시연에서 모형을 세워둔 채 두면 그렇게 동작한다.

- [ ] **ETA 반영 (선택)** — `EXTEND <구역값> <ETA>`에서 ETA가 `-`가 아니면:

      ```c
      need = ceil(eta * ETA_SAFETY_MARGIN - greenRemaining);   // 부족분
      if (need > zoneMax) need = zoneMax;                       // 구역값이 상한
      if (need <= 0) need = 0;                                  // 제시간에 건넌다
      ```
      ETA가 `-`면 `need = zoneMax`. **구역값이 상한이므로 속도는 연장을 깎기만 하고
      늘리지 않는다** — ETA가 틀려도 안전한 방향의 오차다.

- [ ] **무신호 워치독** — 2~3초간 아무 메시지도 안 오면 파이가 죽었거나 USB가 빠진 것이다.
      `NORMAL`로 되돌리고 부저를 끈다.

- [ ] **`FALL` 수신 시 신호를 어떻게 할 것인가 — 팀 합의 필요.**
      부저만? 차량 신호 적색 유지? 연장 중단? 쓰러진 사람은 스스로 못 건너므로
      연장으로 해결되는 상황이 아니다. 무한 연장은 교차 방향 차량을 막아 2차 사고를 부른다.

### 아두이노가 쓸 값 (근거는 `config/config.py`에 있음)

| 값 | 숫자 | 근거 |
|---|---|---|
| `REMAINING_TIME_THRESHOLD_SEC` | 5 | 1회 최대 연장량과 동일 (설계 논리, 팀 확인 대상) |
| `MAX_TOTAL_EXTENSION_SEC` | 10 | 강진군 자동연장 "허용된 시간(5~10초)"의 상한 |
| `ETA_SAFETY_MARGIN` | 1.25 | 경찰청 보행속도 1.0→0.8m/s 완화 비율 |

**숫자만 옮겨 적지 말고 근거도 함께 볼 것.** 발표에서 "왜 5초인가"에 답해야 한다.
