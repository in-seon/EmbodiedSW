# 스마트 횡단보도 — 보행자 잔류 감지 기반 신호 연장 + 쓰러짐 감지

라즈베리파이 카메라로 횡단보도를 지켜보며 두 가지를 판단한다.

1. **아직 다 건너지 못한 사람이 있는가** → 보행 신호를 연장한다
2. **쓰러진 사람이 있는가** → 부저를 울린다

라즈베리파이의 판단을 기반으로, 아두이노가 신호등·부저·7세그먼트를 제어한다.

---


## 동작 원리

### 카메라 구도와 기준점

카메라는 **보행자 신호등에 부착되어 횡단보도를 사선으로 내려다본다**.

사람의 위치는 bounding box **중심이 아니라 아래쪽**을 기준으로 잡는다. 중심점은 사람 키의 절반만큼 떠 있어서, 사선 각도에서는 실제 서 있는 지점보다 카메라 쪽으로 당겨진 위치로 잘못 판정된다.


### 화면이 아니라 실거리로 나눈 5구역

횡단보도를 걷는 방향을 따라 5개 구역으로 나눈다.

```
진입 끝 ┃ 1 │ 2 │ 3 │ 4 │ 5 ┃ 반대 끝
        └───┴───┴───┴───┴───┘
```

화면상 균등 분할은 실제로는 전혀 균등하지 않다. 사선 구도에서는 먼 쪽 1픽셀이 가까운 쪽 1픽셀보다 훨씬 긴 거리를 나타내기 때문에 그대로 두면 횡단보도의 진짜 한가운데가 3번이 아니라 4번 구역에 들어간다.

그래서 네 꼭짓점과 실제 치수로 **호모그래피**를 만들어 평면 좌표(cm)에서 5등분한 뒤 픽셀로 되돌린다. 

### '진척도'를 통한 연장 판단

구역 번호를 그대로 보내면 진입 방향에 따라 의미가 뒤집힌다. 물리적으로 같은 2번 구역이라도, 1번 쪽에서 들어온 사람은 대부분 남았고 5번 쪽에서 온 사람은 거의 다 건넜다. 그래서 파이가 track별 진입 방향을 보정해서 항상 같은 뜻으로 통일해 보낸다.

```
진척도 1 = 방금 진입          진척도 5 = 거의 다 건넘
```

방향은 첫 검출 구역으로 판별한다. 중앙에서 처음 보이면 아직 모르는 것으로 두고, 이후 구역이 바뀌는 방향으로 확정한다.

여러 명이면 **가장 작은 값**(가장 덜 건넌 사람)만 보낸다. 기준표가 단조 감소이므로 그 사람이 항상 가장 부족하고, 나머지는 볼 필요가 없다.

### 잔류 확정과 검출 끊김 대응

검출 흔들림 하나로 신호가 오락가락하면 안 되므로, 횡단보도 안에서 **연속 몇 프레임** 검출돼야 '확정 보행자'로 본다(`ZONE_RESIDENCY_FRAMES`).

YOLO는 가림·모션블러에서 한두 프레임씩 사람을 놓치는 것이 정상이다. 그때마다 카운트를 0으로 되돌리면 확정 보행자가 좀처럼 나오지 않고, 에러 없이 조용히 연장만 사라지므로 이에 대한 대응을 둔다.

- **미검출 유예**(`TRACK_GRACE_FRAMES`) — 몇 프레임 안 보여도 상태를 지우지 않는다. 다만 안 보이는 동안 카운트는 동결한다.
- **track_id 재발급 상속**(`TRACK_INHERIT_DISTANCE_CM`) — 추적기가 같은 사람에게 새 ID를 주면, 직전에 사라진 트랙의 발 위치 근처에 나타난 새 ID를 같은 사람으로 보고 상태를 물려준다.

 상속이 없으면 새 ID는 진입 방향을 모르는 상태가 되어, 거의 다 건넌 사람(구역 4)이 "방금 진입"(진척도 2)으로 보고되고 진척도가 오히려 감소하면서 연장이 계속 다시 붙는다.


### 쓰러짐 감지

같은 프레임, 같은 추론 결과를 쓴다. 포즈 모델(`yolov8n-pose`)의 키포인트에서 **어깨 중점 → 엉덩이 중점** 벡터가 수직에서 얼마나 기울었는지 본다.

- **발동**: 쓰러짐 후보가 일정 시간 유지되면 확정. 짧은 미검출은 무시하고 카운트를 이어간다.
- **해제**: 확정 이후 '정상 자세 또는 횡단보도 이탈'이 연속으로 유지돼야 해제한다.

## 시리얼 프로토콜

| 파이 → 아두이노 | 의미 |
|---|---|
| `normal` | 횡단보도에 확정 보행자가 없음 |
| `zone1` ~ `zone5` | 가장 덜 건넌 사람의 진척도 |
| `fall` | 쓰러짐 확정 |

| 아두이노 → 파이 | 의미 |
|---|---|
| `READY` | 부팅 완료 (파이가 이걸 기다린 뒤 전송을 시작한다) |


### 전송 정책

상태가 바뀔 때 즉시, 그리고 1초마다 한 번 더 보낸다.

초당 수집 줄을 아두이노가 받게 되면 아두이노의 수신 버퍼가 넘치고, 응답까지 하면 그 송신 시간에 아두이노 루프가 묶인다. 그러나 변화 시에만 보내면 그 한 줄을 놓쳤을 때 아두이노가 계속 예전의 상태로 남는다. 주기적 재전송을 통해 유실을 자동 복구하고, 아두이노는 이걸 워치독으로 사용할 수 있다.

## ⚠️ 지금 수치는 모형 기준이다 — 실제 횡단보도에는 조정이 필요

이 저장소의 값들은 **축소 모형(폭 19cm × 길이 29.2cm)** 에서 실측·조정한 것이다. 실제 횡단보도에 적용하려면 아래를 다시 정해야 한다.

### 반드시 다시 재야 하는 값

| 값 | 지금 (모형) | 실제 적용 시 |
|---|---|---|
| `CROSSWALK_REAL_WIDTH_CM` / `LENGTH_CM` | 19 / 29.2 | 실제 횡단보도 치수(cm). 이 값이 호모그래피와 구역 분할 전체를 결정한다 |
| `TRACK_INHERIT_DISTANCE_CM` | 6.0 | 구역 하나의 길이보다 작아야 한다.  |
| 아두이노 1회 연장량 / 누적 상한 | 2초, 누적 10초 | 교툥 법규에 맞게 연장 |


### 카메라 관련

| 값 | 지금 | 실제 적용 시 |
|---|---|---|
| `FOOT_POINT_OFFSET_RATIO` | 0.1 | 실제 사람은 검출 박스가 발밑에 더 정확히 맞아 0에 가까울 수 있다. |
| `DETECTION_CONFIDENCE_THRESHOLD` | 0.2 | 모형이 작아 낮춰 둔 값. 실제 사람은 훨씬 잘 잡히므로 올릴 수 있다 |
| `DETECTION_IMGSZ` | 320 | 파이 성능에 맞춘 값으로 실제 적용 시 높은 해상도 사용.  |
| `FALL_CONFIG["fall_angle_deg"]` | 20 | 실제 사람 쓰러짐 keypoint에 맞게 조정 |

### 구역 캘리브레이션

카메라를 **최종 위치에 고정한 뒤** 횡단보도 네 꼭짓점을 순서대로 클릭한다.

```bash
python tools/zone_calibrator.py --width-cm 19 --length-cm 29.2
```

- 클릭 순서: 시작-왼쪽 → 시작-오른쪽 → 끝-오른쪽 → 끝-왼쪽
- `width` = 걷는 방향과 수직인 변, `length` = 걷는 방향 변
- 치수가 없으면 속도가 px/s로만 나오고, 구역이 화면 기준으로 나뉘어 실제 거리로는 균등하지 않다
- 카메라를 옮기거나 해상도를 바꾸면 좌표와 호모그래피가 모두 무효가 되어 다시 해야 한다

### 실행

```bash
python main.py                # 전체 (신호 연장 + 쓰러짐 감지)
python main.py --mode fall    # 쓰러짐 감지만 (구역 설정 없이도 동작)
python main.py --no-serial    # 아두이노 없이 판정만 확인
python main.py --display      # 창을 띄워서 확인 가능
```
